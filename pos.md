Project value

## Make fast restaurant work stay clear across screens, modes, and input devices.

### What the design needed to achieve

- ✓

Scale type, spacing, popups, and controls across three terminal sizes.

- ✓

Use one keyboard and keypad across login, search, payment, and approval.

- ✓

Organize each workflow around its ticket, states, behavior, and prototype.

Problem

### One product serves many tasks.

Order entry, search, payment, approval, customer accounts, printing, and service modes share one system.

Risk

### Every exception costs time.

Different layouts and input behavior slow staff during busy service and create more training work.

Direction

### Turn patterns into a system.

Responsive guidance and shared components reduce repeated decisions across product and engineering.

Design decisions

## Build reusable rules before adjusting individual screens.

01

### Start from real terminal sizes

Responsive foundation

The 26-page responsive file covers 1366 by 768, 1366 by 1024, and 1024 by 768 terminals.

Intended impact

Each layout decision has a clear reference size and manual device check.

02

### Research search behavior

Pattern study

A 142-participant placement study guided search position, button behavior, and suggestions.

Intended impact

Staff find search where they expect it and understand how results will respond.

03

### Share one keyboard

Common input

The Bar Tabs keyboard became the shared POS input for search, cash payment, manager override, and login in GA13.

Intended impact

Staff reuse the same input pattern across devices and tasks.

04

### Design for physical inputs

Device behavior

Touch, keyboards, scanners, cards, drawers, printers, scales, and payment devices all need clear ownership and recovery.

Intended impact

Disconnected, delayed, duplicate, and retry states become part of the workflow.

Product proof
